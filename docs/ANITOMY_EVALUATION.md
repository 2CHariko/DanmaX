# Anitomy 接入可行性验证

日期：2026-10-16。结论：旧版可在现有 Windows x64 / C++20 / Qt 6.11.0 工具链中静态编译，适合作为文件名解析的补充；不能未经适配直接替换规则解析器。后续已按用户授权接入规则＋Anitomy 混合适配器及失败恢复弹窗，大语言模型仍为后续候选。以下可行性数据保留为接入前基线，实施状态见文末。

## 验证范围

当前解析器依赖有限的发布组、分隔符和技术标签正则。截图中的 `[KitaujiSub]` 没有被移除，污染了番名和搜索关键词；下划线、点分隔等格式也有缺口。Anitomy 的文件名分词和字段识别可补足这部分能力，但不负责跨语言番剧身份、在线搜索召回或数据库对应关系。

本轮新增根 CMake 默认关闭的 `DANMAKU_BUILD_ANITOMY_PROBE`，构建独立 Qt Test 验证程序。生产 `danmaku_runtime`、`MediaTitle`、QML、自动加载流程和开发运行目录未因本轮验证而改变；既有未提交的自动匹配实现保留。

## 实测与边界

环境：Windows 11，MSVC 19.44.35228 / 工具集 14.44.35207，Windows SDK 10.0.26100.0，Qt 6.11.0。编译命令为 `/std:c++20`，报告的 `__cplusplus` 为 `202002`，`wchar_t` 为 16 bit。QString 与 `std::wstring` 的中文、日文、补充平面字符转换及解析专项通过。Anitomy 库本身不链接 Qt。

| 检查 | 最终结果 |
|---|---|
| 根项目开启验证目标，Release CTest | 5/5，0.30 秒 |
| 根项目开启验证目标，Debug CTest | 5/5，0.58 秒 |
| 验证程序内部 Qt Test | 各 7 passed、0 failed，含初始化／清理 |
| 默认关闭验证目标的 `windows-core` | 4/4，0.10 秒 |
| 项目外目录执行准备及 Debug 验证脚本 | 通过 |

CTest 的 5 项包括 4 项既有核心测试和 1 项验证程序。Qt Test 通过表示预期行为、风险观察及报告生成检查通过，不代表以下全部语料正确解析。没有运行完整生产 GUI 测试、真实播放器、覆盖层性能或发布部署测试。

### 上游语料

锁定源码自带 `test/data.json` 共 182 条，保留其分隔符和忽略字符串选项，按已标注字段比较，数组逐项比较：

- 1,158 项字段检查，47 项不一致。
- 151/182 条的全部已标注字段符合期望。
- 164/182 条的已标注番名／季数／集数字段符合期望。

这是固定旧版对其语料的测量，不是“182 条全部通过”，也不是实际用户命名准确率。未标注字段不参加比较，不能据此证明没有额外误识别。全部差异在 `comparison.json` 的 `upstream.mismatches` 中；例如 `[Keroro].148...`、全括号番名及部分数字标题存在缺口。

### 项目专项样本

共 40 条：24 条普通单集预期提取样本、16 条需要手动确认或拒绝普通单集自动处理的边界观察。除截图文件名来自真实反馈外，其他为针对项目构造的回归样本，并非随机抽样准确率测试。

24 条正例比较规范化番名、季数与集数，当前解析器符合预期 9/24；Anitomy 加 Windows 路径去前缀和 NFKC 适配后为 19/24。这里仅比较提取结果，不执行自动加载决策。

| 类别 | 观察 |
|---|---|
| 截图文件名 | 正确提取 `Kimi ga Shinu made Koi wo Shitai`、`01`、`KitaujiSub` |
| 未知字幕组、下划线、点分隔、`2nd Season`、`S02E03` | 相应正例提取符合期望 |
| 中文番名＋`- 12`、日文名、补充平面汉字 | 相应正例提取符合期望 |
| 驱动器／UNC 路径 | 应用侧先去路径；不能直接传完整路径，也不能拆开 `Fate/stay night` |
| 全角 `ＥＰ０１` | 原始输入未识别集数；NFKC 后可识别 `01` |
| `葬送的芙莉蓮 第 12 集` | Anitomy 番名残留“第”；现有解析器正确，需回退 |
| `[喵萌奶茶屋][葬送的芙莉莲][12]...` | Anitomy 返回 false 且缺番名；现有解析器可识别，需回退 |
| `Test 第二季 第3话` | 未提取季数，集数字段为 `3话`，不能直接转数字后接受 |
| `Test 第十二话` | 两者都未正确提取，仍需人工或单独扩展 |
| `Test EP12.5v2` | Anitomy 提取为 `12`，将 `5v2` 当集标题；现有解析器保留 `12.5`，必须防止退化 |
| `01-02`、`01 & 02` | 返回多个集数，不能取第一个作为单集 |
| `01 - 02` | 可能仅返回 `01`，另一数字当集标题；只有一个集数字段仍不足以判定普通单集 |
| SP／OVA／OP／ED、中文特别篇 | 即使返回正集数，也必须通过内容类型校验 |
| `Spice and Wolf 2` | 把 `2` 当集数；弱格式仍需确认，不能只依据 `Parse == true` 自动加载 |

### 公网只读复核

读取验证程序生成的截图行，再请求 `https://danmaku-api.152468.xyz` 的 `/api/v2/search/anime`：

- 当前结果 `[KitaujiSub] Kimi ga Shinu made Koi wo Shitai`：0 条。
- Anitomy 结果 `Kimi ga Shinu made Koi wo Shitai`：唯一条目 `19189`，`与你相恋到生命尽头`。
- 详情含罗马音别名 `Kimi ga Shinu made Koi o Shitai` 和第 1 话（`191890001`）。

记录在 `out/validation/anitomy-probe/online-check.json`。本轮只查询搜索和详情，未下载弹幕、创建关联或通过真实 SMTC 自动加载。服务响应可能变化，仅记录本次观测。

Anitomy 输出的仍是原文件名罗马音。生产当前的“展示标题规范化后必须完全同名”规则仍会阻止跨语言自动选择；详情别名核对、`o / wo` 差异等需后续单独验证。加入 Anitomy 不等于完成截图的全流程修复。

## 初次验证时建议的接入边界

### 本机真实媒体库补充（2026-10-16）

用户指定目录的全部可枚举视频文件已加入验证：1,551 个文件中共 466 个视频（421 MKV、45 MP4），扫描无错误。30 个顶层目录中 28 个含视频，另有根目录单片；未发现视频的两个目录同样完成扫描，但不检查压缩包内部。逐文件只读文件名与目录元数据，没有读取视频内容或发送全库在线搜索。

Anitomy 可提取单集字段 365 个，当前解析器返回有效字段 357 个；两者均有字段 333 个，其中集数冲突 0，规范化番名／季度差异 183。字段数量不代表准确率：Anitomy 独有的 32 个结果全部是 SP、PV、OP/ED、OAD、采访等性质的文件；当前结果有 179 个仍含发布组，其中 155 个 Anitomy 可提供完整字段并分离发布组。

真实退化集中在 24 个全括号中文文件名：能取集数但丢失番名、Parse 返回 false。另有 77 个无集数文件，包含电影、特别篇及预告等，不能全部计作普通正片解析失败。`2nd Season` 的 11 个样本可正确提取第二季；菜单、`NCOP_EP12` 等仍可能产生普通数字，必须先做类型和分隔符校验。库中同时存在累计编号与按季度重新编号的发布形式，不能据此推导线上集数偏移。

根项目 Release／Debug CTest 各 5/5，完整媒体库的两种配置 466 行结果逐项一致。原始结果、逐文件 CSV、目录表和本轮结论位于 `out/validation/anitomy-library/`；目录与文件明细仅保存在忽略产物中。新增 `scripts/test-anitomy-library.ps1 -LibraryPath <媒体目录> [-NoBuild]` 可重复执行，不硬编码本机媒体路径，不改变生产解析器。审计风险标签为诊断规则，不是已实现的自动加载策略。

### 后续生产适配

1. 在 `MediaTitle` 所属基础设施层增加适配器，维持 1,024 字符上限、Windows 路径处理和 NFKC，使用局部解析对象，不修改领域核心、QML 或逐帧渲染。
2. Anitomy 提供发布组、干净番名、季数和集数候选；保留中文、小数集数能力。先检查原始输入的合集／特殊篇／零季／零集／弱格式，冲突交给用户，不能从任意成功结果中挑一个自动加载。
3. 数字必须完整解析；检查多集、替代集数、季数及 `Parse` 返回值。不能接受截断的小数或区间端点。
4. 线上使用详情别名核对身份，确认后保存番剧 ID，后续切集复用；零结果仍需手动纠正入口。解析规则会影响缓存／关联标题键，正式接入须验证旧关联兼容和迁移。
5. 扩展真实文件名回归。大语言模型仅保留为后续候选，不在本轮增加模型、推理框架或常驻进程。

## 复现与证据

PowerShell 7，入口仍为根 CMake；脚本不依赖调用者当前目录。首次准备是显式联网步骤：

```powershell
./scripts/prepare-anitomy.ps1
./scripts/test-anitomy-probe.ps1 -Configuration Release
./scripts/test-anitomy-probe.ps1 -Configuration Debug
```

已有缓存时使用 `prepare-anitomy.ps1 -Offline`。构建位于 `out/build/anitomy-evaluation-{release,debug}/`，报告位于 `out/validation/anitomy-probe/{release,debug}/`，包括 `comparison.json`、`qtest.txt`、`ctest.xml` 和工具链身份记录。项目或工具链身份变化时，脚本拒绝复用旧构建缓存。

验证源码：`tools/anitomy-probe/ProbeTests.cpp`。正式应用现已依赖该锁定版本，首次构建前需显式执行准备脚本；配置／构建不联网。验证程序不随应用部署，打包时附带 Anitomy 许可证、锁定清单和校验过的源码归档。

## 混合适配器接入后的验证

- `IMediaTitleParser` 输出候选，规则与 Anitomy 为内置适配器；共享仲裁检查特殊片段、范围、零集、显式／弱集数和冲突。Anitomy 清理发布组，规则保留中文与小数集数。新增适配器可通过构造函数注入；大语言模型需在同步端口之外异步执行。
- 截图文件名提取为 `Kimi ga Shinu made Koi wo Shitai`／第 1 集；搜索单候选还需核实详情别名。测试覆盖该罗马字与详情独立助词 `o/wo` 差异，不允许通用编辑距离猜测作品或季度。
- 使用先前指定目录的同一份 466 文件清单重新验证：混合策略 352 个可进入自动匹配、72 个需确认、42 个无法识别。24 个全括号中文《未来日记》保留番名与集数，截图同系列 13 个文件全部提取。报告 `out/validation/hybrid-library/audit.json` 包含每文件结果。这里统计的是本地解析策略，不是线上匹配率或逐文件人工标注准确率；未读取视频内容、未批量请求公网服务。
- 旧规则基线保持独立，报告中的 `current` 明确调用 `parseRuleMediaTitle`，避免混合解析上线后改变既有比较口径。原始 Anitomy 字段与混合策略分开记录。
- 本次匹配失败恢复事务通过信号请求指定会话独立暂停／恢复，确认暂停采样后才获得恢复资格；切集、换会话、过期、控制失败和用户手动恢复会阻止错误恢复。真实播放器端到端行为仍需实机验收。
