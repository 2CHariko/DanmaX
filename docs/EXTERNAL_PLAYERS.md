# 外部播放器预设

当前提供 PotPlayer x64 与 VLC 3.x x64 预设。设置页通过“管理播放器”弹窗选择默认预设、自动发现安装、手动选择程序或输入路径。名称、启动参数与同步行为由适配器实现，不开放用户编辑，也不提供自定义播放器增删入口。PotPlayer 使用 SMTC，VLC 使用本地 HTTP 同步，无需安装 SMTC 插件或配置端口、密码。

修改先进入草稿，保存后原子提交；取消、Escape 或离开设置页丢弃修改。保存失败保留草稿，配置修订冲突拒绝覆盖。编辑草稿不会中断现有播放，生效路径变化才取消旧打开事务。

## 自动发现与路径验证

两个预设均从 HKCU/HKLM 的 App Paths（含 WOW6432Node）发现安装，不扫描磁盘或隐式 PATH。候选先验证，再按规范路径去重。只有一个有效位置时写入草稿；多个位置时列出候选，由用户明确选择；没有位置时提示手动选择。自动打开视频只接受唯一发现结果，否则提示选择程序。已保存路径失效时明确报错，不替换成其他安装。

选择、保存以及启动前均验证：

- 绝对路径、文件存在、可读，名称为 `PotPlayerMini64.exe`。
- DOS/PE 标记、AMD64 架构、PE32+ GUI 可执行文件，拒绝 DLL、截断头、越界节表/原始段与不在可执行段中的入口点。
- 存在产品身份版本资源时，ProductName、FileDescription、OriginalFilename 至少一项包含 PotPlayer；无身份元数据的便携版本允许通过结构校验。

VLC 复用上述 PE 结构校验，文件名必须为 `vlc.exe`，可用产品身份须匹配 VLC、主版本须为 3；同时要求安装中的 `lua/intf/http.luac` 与 `lua/intf/modules/httprequests.luac` 可读。精简掉 Lua HTTP 的安装不可用，VLC 4 尚未提供预设。

这是程序兼容性检查，不是签名或安全可信认证。检查不运行所选 EXE。文件选择失败保留原路径；手动输入在回车或失焦后验证，错误内容保留供修正且禁止保存，生效路径保持原值。粘贴路径可带成对双引号和首尾空白；清空路径恢复自动发现。路径有效也不等于播放器已提供可用 SMTC；播放事务仍须核实真实会话、时间轴与目标文件名。

## 配置文件

数据目录 `player-presets.json` 使用 `QSaveFile` 原子写入，上限 64 KiB：

```json
{
  "version": 1,
  "defaultPreset": "potplayer",
  "paths": { "potplayer": "", "vlc": "" }
}
```

空路径允许保存（包括没有修改时），表示首次打开时尝试自动发现。路径相关错误统一显示在路径框下方，不在卡片底部重复提示。名称、参数、会话规则不持久化。未知版本、未知预设、非法类型或路径格式使配置不可用，原文件保留并禁止回退启动；修复或移走原文件后重启。载入时允许保留暂时离线的安装路径，管理窗口显示错误，保存和启动会重新验证。手工编辑应先退出应用，不监视外部修改。

不读取或迁移旧 `external-players.json` 或 INI 中的 `potPlayerPath`，也不删除旧文件。首次采用此版本时重新自动发现或选择路径。

## 启动与同步

PotPlayer 使用独立参数列表 `{视频绝对路径, /current}`，不经 shell。公共 Windows 进程层检查同名实例数量和实际路径，拒绝多实例、路径冲突及不可确认状态。进程成功启动后继续等待目标 SMTC 会话的新鲜采样；原媒体基线、事务代次及完整文件名/去扩展名匹配保持独立。同名媒体需用户核对画面后确认。

媒体库在目标确认后恢复历史位置，再准备 XML／关联／缓存或在线弹幕。定位需能力检查、请求成功及新采样读回；失败保留历史并提供重试／按当前位置继续。VLC 定位命令再次验证连接、URI 与播放列表项；PotPlayer 使用 SMTC 定位请求。能力报告不替代真实读回验收。待确认事务在取消、配置变更或新视频时失效；已确认任务持有配置快照。领域核心、时钟和渲染器不依赖具体播放器。双路径和记录规则见 [说明](DUAL_WORKFLOWS.md)。

VLC 由 DanmaX 启动独立受控实例，保留普通 VLC 窗口；后续打开复用同一个存活的受控实例。完整文件 URI 与新的播放列表项共同确认目标，同名文件无需 SMTC 的人工确认。已有普通实例没有控制接口时不会被接管。退出 DanmaX 断开连接，不关闭播放器；重新启动 DanmaX 后再次打开视频会建立新连接。

弹幕页会在后台约每秒发现一次支持的 VLC 3.x x64 进程，以 PID＋创建时间区分实例。已建立的 DanmaX 连接正常可选，显示当前视频名称；普通进程显示“未建立同步连接”，灰显且不能绑定，并提示先将 VLC 设为默认外部播放器、通过“打开视频”建立连接。受控实例不重复列出，未选中的实例退出也会更新列表。发现进程不会读取其命令行或猜测密码，不会自动修改 VLC 配置。本轮不持久化认证信息，重启应用后的自动重连仍未提供。

连接只监听 `127.0.0.1`，使用每次启动生成的随机认证密码，并核实监听端口属于绑定的 PID 和进程创建时间。接口资源与受控缓存位于应用缓存目录的 `players/vlc/`，不改写 VLC 安装或用户配置。HTTP 请求异步、有超时与响应大小限制，同一连接最多一个请求在途；过期代次和错误媒体的控制被拒绝。凭据不写入配置或日志。

自带 Lua 状态端点读取原始小数秒位置、时长、实际倍率和文件 URI。约 100ms 轮询不代表 VLC 输入时钟每 100ms 更新；重复的播放位置不重复校准时钟，长时间停滞按不可用处理。暂停／恢复控制在服务端再次核对 URI 和播放列表项，避免切集后控制错误媒体。VLC 退出、连接失败或端口被其他进程占用时提示重新打开视频。

## 扩展预设

`IExternalPlayerAdapter` 负责名称、候选发现、EXE 校验、实例预检、参数、连接方式与文件选择过滤器。`ExternalPlayerRegistry::presets()` 从注册适配器生成固定预设列表。`MediaMonitor` 统一分发 `SmtcBackend` 和 `VlcHttpBackend` 的采样、控制及会话列表；受控启动通过 `VideoOpenService` 的连接准备阶段进入同一自动弹幕工作流。新增播放器须实现适配器并注册，补充专属启动、媒体控制和同步验收，不能仅增加用户填写字段便宣称支持。`VideoOpenService` 可注入注册表，测试钩子仅替代进程副作用。

验证结果及尚未验收边界见 [FRAMEWORK_STATUS.md](FRAMEWORK_STATUS.md)。

本机实测 VLC 的定位与关闭后续播通过。PotPlayer 的 SMTC 报告支持定位、请求也返回成功，但部分非零目标的读回偏差超过 1 秒；精确续播暂未验收。媒体库会按恢复失败保留历史，提供重试或按当前位置继续，不以请求成功冒充续播成功。从头播放、XML 切换及暂停／恢复已分别实测。
