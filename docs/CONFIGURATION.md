# DanmaX 配置文件说明 (settings.ini)

DanmaX 采用纯 UTF-8 编码的 `settings.ini` 文件作为统一配置存储。静态便携版默认将配置文件保存在与 `DanmaX.exe` 同级的目录下；开发运行配置与日志位于 `out/run/<预设>/`。首次运行应用会自动生成带有完整中文注释的配置文件模板。默认配置模板请参考 [settings.example.ini](settings.example.ini)。

> **格式注意**：DanmaX 0.2+ 不再读取或迁移历史版本的 `settings.json` 或旧版 `config.ini`。新版本从干净的 `settings.ini` 或代码内置默认值启动。

## 1. 配置项速查字典

配置按主要功能分区 (Section)，实际字段与默认值以应用 Schema 为准：

| 分区 (Section) | 键名 (Key) | 类型 | 允许取值区间 / 候选值 | 默认值 | 用途与核心行为说明 |
|---|---|---|---|---|---|
| `[Meta]` | `formatVersion` | 整数 | `1` | `1` | 配置文件格式版本。非 1 版本或缺失版本不自动迁移。 |
| `[Online]` | `danmakuServers` | JSON 数组字符串 | 有效 HTTP/HTTPS URL 列表 | `["https://danmaku-api.152468.xyz"]` | 弹弹play 兼容服务器地址列表。按顺序回退，空数组 `[]` 禁用在线搜索。 |
| `[Appearance]` | `theme` | 字符串 | `"system"`, `"light"`, `"dark"` | `"system"` | UI 主题。高对比度系统模式下优先跟随系统，不强制浅深色。 |
| `[Appearance]` | `fontFamily` | 字符串 | 1~4096 字符字符串 | `"Microsoft YaHei"` | 弹幕渲染字体名称。优先匹配系统已安装字体，缺失字形由系统回退。 |
| `[Appearance]` | `fontSize` | 整数 | 10 ~ 72 (逻辑像素) | `24` | 弹幕基准字号。XML 源字号以 25 为基准按比例动态缩放。 |
| `[Appearance]` | `strokeWidth` | 整数 | 0 ~ 6 (逻辑像素) | `1` | 弹幕文字外描边宽度。`0` 表示无描边。 |
| `[Appearance]` | `opacity` | 浮点数 | 0.05 ~ 1.0 (5% ~ 100%) | `0.85` | 弹幕层整体不透明度。仅作用于弹幕，不改变控制面板透明度。 |
| `[Danmaku]` | `speed` | 整数 | 30 ~ 1500 (逻辑像素/秒) | `180` | 滚动弹幕移动速度。播放中调整保留当前位置与进度，不重新加载。 |
| `[Danmaku]` | `fixedSeconds` | 浮点数 | 1.0 ~ 30.0 (秒) | `5.0` | 顶部与底部固定弹幕的显示时长。暂停时不计入寿命消耗。 |
| `[Danmaku]` | `maxActive` | 整数 | 50 ~ 5000 | `500` | 屏幕同时渲染的最大弹幕数量上限。调低时按先来先到原则保留较早对象。 |
| `[Danmaku]` | `maxTracks` | 整数 | 1 ~ 60 | `18` | 纵向最大轨道数量上限。实际可用行数还受屏幕高度与行高物理限制。 |
| `[Danmaku]` | `lineSpacing` | 浮点数 | 0.0 ~ 2.0 (0% ~ 200%) | `0.2` | 轨道间距占行高的比例。比例越大，同屏容纳轨道数越少。 |
| `[Danmaku]` | `overlap` | 布尔值 | `true`, `false` | `false` | 轨道占满时是否允许重叠。关闭时无安全空位的新弹幕直接丢弃。 |
| `[Rendering]` | `textureBudgetAuto` | 布尔值 | `true`, `false` | `true` | 文字图片预算自适应模式。`true` 依据活跃文字按需分档自动扩缩。 |
| `[Rendering]` | `textureBudgetMiB` | 整数 | 32 ~ 1024 (MiB) | `512` | 图片显存预算上限（自动模式为上限，手动模式为固定值）。非预分配。 |
| `[Sync]` | `timeOffset` | 浮点数 | -120.0 ~ 120.0 (秒) | `0.0` | 仅跟随播放器使用。正值提前出现，负值延后出现；独立模式忽略此值，保留供下次跟随使用。 |
| `[Sync]` | `targetSession` | 字符串 | SMTC 来源应用 ID | `""` | 播放页选择后记住；会话消失时等待相同 ID，再次出现自动连接，不切换其他播放器。留空取消绑定。 |
| `[Sync]` | `automaticDanmaku` | 布尔值 | `true`, `false` | `false` | 开启标题识别、缓存优先匹配、在线唯一匹配下载及连续切集。手动来源操作／停止会暂停本次运行的自动匹配。 |
| `[Player]` | `potPlayerPath` | 字符串 | 64 位 PotPlayer EXE 的绝对路径 | 空 | 打开视频时使用的程序路径；留空自动发现，便携版可手选。与 `targetSession` 的 SMTC 来源应用 ID 分开保存。已保存路径失效时不静默换用其他安装。 |
| `[Window]` | `screenIndex` | 整数 | 0 ~ 32 | `0` | 覆盖层所在显示器索引。索引超出实际屏幕数时自动回退主显示器。 |
| `[Window]` | `onTop` | 整数 | `0`, `1` | `1` | 0=不置顶，1=置顶。统一使用窗口事件恢复与 100 ms 周期检查，层级正常时不重复提升；同格式旧值 2/3 读取后迁移并保存为 1。 |
| `[Window]` | `foregroundOnly` | 布尔值 | `true`, `false` | `false` | 仅播放器处于前台时显示覆盖层。适用于同步模式；无法识别时建议关闭。 |
| `[Diagnostics]` | `debug` | 布尔值 | `true`, `false` | `false` | 是否在覆盖层展示性能与调试统计信息（更新率、内存、图片节点等）。 |
| `[Diagnostics]` | `debugPosition` | 字符串 | `"top_left"`, `"top_right"`, `"bottom_left"`, `"bottom_right"` | `"top_left"` | 调试统计信息在屏幕上的锚定角落位置。 |
| `[Logging]` | `logLevel` | 字符串 | `"DEBUG"`, `"INFO"`, `"WARNING"`, `"ERROR"` | `"INFO"` | 日志输出的最低过滤级别。 |
| `[Logging]` | `logToFile` | 布尔值 | `true`, `false` | `true` | 是否写入 `app.log` 磁盘日志。单文件限 2 MiB 并保留 1 份轮转备份。 |
| `[Playback]` | `lastFile` | 字符串 | 任意路径字符串 | `""` | 最近一次加载的本地 XML 文件绝对/相对路径。启动时不自动加载播放。 |

## 2. 手工编辑语法规则

在未运行 DanmaX 实例时，用户可使用任意文本编辑器（推荐 VS Code, Notepad++ 等支持 UTF-8 的编辑器）直接修改 `settings.ini`：

1. **实例互斥**：在手动编辑前**必须退出所有 DanmaX 进程**。程序在运行期间不会主动监听磁盘文件的外部变更，且界面保存时会覆盖外部改动。
2. **编码与字符集**：必须保持 **UTF-8（无 BOM 或带 BOM 均可）** 保存。
3. **布尔类型**：推荐写作 `true` / `false`，解析时亦兼容 `1` / `0`。不接受 `yes` / `no` / `on` / `off`。
4. **数值类型**：浮点数必须使用英文句点 `.`，禁止使用千分位逗号或本地化逗号（如德语环境逗号）。
5. **字符串与路径**：
   - 字符串值建议包含在英文半角双引号 `""` 中。
   - 文件路径推荐使用 POSIX 正斜杠 `/`，例如：`lastFile="D:/Danmaku/sample.xml"`。
   - 若使用 Windows 反斜杠，必须进行双重转义，例如：`lastFile="D:\\Danmaku\\sample.xml"`。
   - 遵循 Qt INI 规则：若字符串首字符为 `@`，需转义为 `@@`。
6. **JSON 数组字符串**（以 `danmakuServers` 为例）：
   - 该字段在 INI 中以转义的 JSON 数组字符串存储，例如：`danmakuServers="[\"https://api1.example.com\",\"https://api2.example.com\"]"`。
   - 清空列表写作 `danmakuServers="[]"`。

## 3. 保存机制、错误恢复与安全备份

1. **防抖合并写入**：界面中的普通滑块或输入框在编辑时即时生效，同时延迟合并 200 ms 后触发原子写盘，退出应用时自动刷新未落盘的修改。
2. **原子写入 (QSaveFile)**：写入操作先生成临时文件，在数据完整无误后通过原子系统调用替换目标 `settings.ini`，避免由于突然断电或程序崩溃产生半截破损文件。
3. **破损备份机制**：若程序在启动读取配置时检测到非法 UTF-8、语法严重破损、文件大于 1 MiB 或版本冲突，程序**不会直接盲目覆盖原文件**，而是在第一次触发保存前，将破损的原内容完整备份至 `settings.ini.backup-<UTC时间戳>`，并在界面上向用户展示错误提示。
4. **配置重置与重建**：程序每次保存时均会根据内置的 Schema 自动重建完整的中文注释说明与标准分组，用户自行追加的手动注释或未知扩展字段在保存时将被过滤。

## 4. 关键特性配置进阶

### 4.1 自适应文字图片预算 (`[Rendering]`)
- `textureBudgetAuto=true`：当屏幕上有弹幕流动时，系统根据当前在屏文字排版计算 RGBA 纹理内存需求，在 64 MiB 基线基础上保留 25% 缓冲，并按 128 / 256 / 512 MiB 等分档动态递增。当在屏弹幕密度持续回落超过 10 秒后，自动收缩缓存释放显存。
- `textureBudgetMiB=512`：约束纹理缓存扩张的硬上限。超出此上限的弹幕会自动降级回退至 `QSGTextNode` 矢量文字节点渲染，确保永远不会因为显存超限而丢失弹幕内容。

### 4.2 在线弹幕与本地隔离缓存 (`[Online]`)
- 首页不再提供常驻“在线弹幕搜索”及旧自动确认展开区。卡片“搜索弹幕”与详情选集统一打开搜索弹窗，复用动画／剧集选择、下载／重新下载；唯一匹配时自动载入，歧义时在弹窗确认。手动搜索不请求暂停播放器，成功后关闭弹窗并进入播放页，由用户开始播放；没有播放器时也可搜索和准备弹幕。
- 播放页仅保留“本地 XML”与“已缓存”来源标签。已保存的播放器暂未提供有效媒体状态时显示等待，仍可在弹幕就绪后开始跟随；会话恢复后按其当前位置与暂停状态同步。
- 跟随模式下，指定播放器会话失效／关闭或采样过期后隐藏弹幕层与工具栏；持续失联 1.5 秒后清理在屏对象、轨道及渲染快照，保留弹幕源、播放器绑定、缓存及关联。重新连接使用新鲜位置恢复，不把普通暂停视作关闭；独立播放不受该策略影响。已绑定当前有效播放器的手动搜索弹窗在失联时取消并关闭，自动恢复弹窗随事务失效关闭。会话消失不代表已确认进程退出，主程序保持等待。

### 4.2.1 按播放内容自动匹配 (`[Sync] automaticDanmaku`)

- 默认关闭，在播放页的“跟随播放器”下开启。观察指定应用提供的 SMTC 标题和时间轴，不读取媒体文件内容、不启动播放器；自动匹配失败时可请求暂停与恢复，规则见下文。开启后无需先加载弹幕，标题稳定 600ms 后自动准备并开始跟随；已有媒体位于中途或暂停时使用最新采样位置与状态。
- 支持 `番名 - 01`、`番名 EP01`、`番名 第1集`、`番名 S02E03`、`番名 [01]`、小数集数和常见修订／技术标签。简繁、大小写及常见季度写法用于比较，第二季不降为第一季。单纯空格加数字的弱格式首次需要确认；合集、SP／OP／ED、季数为 0、缺失集数及无法可靠解析的标题留给手动载入，不承诺通用文件名识别或跨语言翻译。
- 优先读取唯一有效的本地缓存（在线服务列表为空时仍可使用）；同一剧集在兼容服务的缓存副本不重复载入，不同剧集 ID 的冲突需确认。缓存未命中时复用已确认的剧集／番剧关联，否则只接受唯一的规范化同名番剧及唯一集数。不会将搜索排名第一当作正确匹配。
- 采用规则＋Anitomy 混合识别；最终无匹配、解析失败或有歧义时，请求指定播放器暂停并弹出“手动匹配弹幕”。显示原始文件名／SMTC 标题，支持选中及复制、修改关键词搜索、确认动画与剧集后载入。仅当本次流程确实暂停播放器时，完成／取消才请求恢复；原本暂停保持暂停。不支持控制或未确认暂停时显示说明，仍可手动搜索。取消按钮与 Escape 跳过当前内容，下一集仍自动匹配；切换文件／会话立即废弃旧弹窗和操作。
- 手动确认的原始标题精确对应以摘要保存，无法解析的文件也能在下次播放复用；可识别内容同时保存番名／集数对应，集数一致时保存番剧对应供下一集使用，并兼容旧解析键。不推导季度累计集数偏移。缓存删除后按已确认 ID 重下；在线复用限当前配置服务，离线缓存仍可使用。不同语言展示标题通过服务详情别名核实，不进行无依据的翻译或通用模糊猜测。
- 关联保存在数据目录的 `media-associations.json`，版本 1，最多 512 条记录（每个番剧／分集占独立记录），写出内容控制在 512 KiB；原子替换，未知版本或损坏文件保留并提示无法保存新关联。可在播放页“忘记本番关联”后重新选择，删除弹幕缓存不删除关联。
- 内容切换立即清除旧弹幕的活动对象、轨道、游标及绘制资源，新内容准备成功后从播放器最新位置开始。暂停冻结，普通跳转不重新检索；同集的技术标签或时长更新不触发重新下载。没有更新标题的换集无法保证识别，同一应用的多个 SMTC 实例仍存在区分限制。
- 手动 XML／在线／缓存操作、停止、卸载或取消自动准备会暂停自动匹配，迟到结果不能接管当前来源。点击“继续自动匹配”恢复；该暂停仅对本次运行有效，重启按保存的开关和播放器选择启动。失败不会在每次媒体采样时重复联网，可显式重新匹配；失联、过期或切集取消正在准备的旧内容。
- 在线弹幕下载后长期保存在 `cache/danmaku/` 目录下，文件名带有来源服务器与剧集参数摘要。
- 换机或备份时，仅需将 `settings.ini` 与 `cache/danmaku/` 文件夹一同复制至新电脑，即可离线保留所有已下载的弹幕剧集。

### 4.3 番剧元信息与封面缓存

- 缓存位于 `AppPaths.cache/metadata/`，`json/` 保存版本化 JSON，`covers/` 保存封面及其索引条目。每个条目包含资源键、成功获取时间和最近使用时间，可独立恢复；资源键摘要隔离 API 来源及搜索参数。
- 缓存目录沿用 `--cache-dir`，未指定时使用数据目录下的 `cache/`。开发运行按预设分别位于 `out/run/windows-debug/`、`out/run/windows-release/`、`out/run/windows-static-release/`，配置、日志和缓存互相独立；动态部署和静态便携版均默认使用 EXE 旁的 `settings.ini`、`app.log` 和 `cache/`，不使用用户级网络缓存。旧 `.local/data/`、`.cache/qml/<Qt 版本>/` 和动态版 `data/` 保留，不自动迁移或覆盖。
- 优先展示本地内容：日历与分集 6 小时、详情 24 小时、搜索 1 小时、封面 30 天内不自动请求。过期后后台更新，失败继续显示旧内容；同一资源失败后自动更新冷却 5 分钟，手动刷新可跳过有效期和冷却。
- 同一次运行中，切回首页直接复用当天仍有效的周历与主推内存数据；冷却期间保留已显示的旧内容，不反复进入加载状态。跨日重新计算今日放送；有效期检查仍每分钟执行，切页不会推迟检查。已访问的封面随图片组件保留，组件销毁或主动清空缓存时释放请求，继续遵守既有下载并发与请求数量上限。
- 日历、高分推荐和今日放送来自周历；主推简介与详情共享番剧条目。分集全部分页通过校验后才替换完整缓存；部分结果只用于当前会话。合法空搜索和空简介也可命中缓存。
- JSON 上限 64 MiB，封面上限 512 MiB，包含索引条目占用；按最近使用时间自动淘汰，保护日历与当前使用内容。无法容纳的新内容仅供当前会话显示，不扩大磁盘预算。容量与有效期暂不提供配置项。
- 只缓存已访问的元信息及已请求的封面，不下载整个番剧库。离线浏览仅覆盖仍保留的内容；过期不直接删除，容量淘汰和主动清空会缩小离线可用范围。
- “设置 → 番剧元信息缓存”显示占用与上限，支持清空并显示结果。清空取消相关请求并废弃旧写入，保留弹幕缓存、文字缓存和用户配置；下一次访问或手动刷新才重新获取。
- 旧 `metadata/calendar.json` 校验后只导入默认 Bangumi 来源，沿用原修改时间；确认新条目成功落盘后移除旧文件。未知格式、损坏或超限条目视为未命中；写入失败记入日志，不阻止展示在线取得的数据。
