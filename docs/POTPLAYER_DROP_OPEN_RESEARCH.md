# 拖入视频并联动 PotPlayer：可行性与实施建议

日期：2026-10-16。状态：用户授权后已实施，详见第 11 节。前九节保留调研时的建议与边界，第 10 节是实现前的接口验证；不能将这些历史建议全部视为当前已实现或已验收能力。

## 1. 结论与首版范围

可以实现。建议把 DanmaX 主窗口作为视频打开入口：用户绑定 PotPlayer 后，拖入一个视频，程序打开该视频、等待对应媒体会话就绪、自动匹配并启动弹幕。继续复用现有 SMTC 同步、混合文件名解析、弹幕缓存、在线来源和匹配失败恢复流程；无需新增第三方依赖、播放器插件或注入组件。

本方案将“拖拽”解释为从资源管理器拖入 **DanmaX 主窗口**。拖入 PotPlayer 自身窗口时，DanmaX 仍只能通过后续 SMTC 更新跟随；监听其他程序的拖放不是首版范围。

建议首版明确如下行为：

- 默认适配 Windows x64 PotPlayer；绑定可执行文件，支持安装版和用户指定的便携版。
- 一次处理一个本地视频，提供同等功能的“打开视频”按钮作为键盘入口。可先接受 `.mp4`、`.mkv`、`.avi`、`.mov`、`.wmv`、`.flv`、`.webm`、`.m4v`、`.ts`、`.m2ts`；这是入口筛选，不是解码能力保证。
- 唯一已有实例优先复用；没有实例时启动。多个 PotPlayer 实例／会话有歧义时交还用户，不能任取一个。
- 拖入视频即启动本次工作流的自动匹配；匹配成功后自动显示弹幕，不要求再按“开始播放”。匹配失败复用现有选集弹窗及已确认暂停／恢复机制。
- 第一版弹幕来源沿用已确认关联／缓存／在线匹配。同目录同名 XML 自动发现可作为后续增强；不把任意当前已加载 XML 直接套给新视频。
- 暂不处理文件夹、批量播放列表、网络 URL、视频加 XML 混合拖入、拖到 EXE 图标、系统文件关联或其他播放器适配。

## 2. 已核实的依据

### 本机 PotPlayer 随附说明

通过 Windows `App Paths` 只读定位到已存在的 `PotPlayerMini64.exe`，并读取其相邻 `CmdLine64.txt` 英文段。说明文件 SHA-256：`155B6FD3C6E7AAE3BA42F3EEFD50D013FAFA8BC1A58D38DC5DD6B3E9A33A9870`。具体安装路径只供本机定位，不写入版本化配置或本文件。

| 项目 | 随附说明中的语义 | 对实现的影响 |
|---|---|---|
| 视频路径参数 | 接受文件、目录或 URL 内容 | 首版只传入经过校验的单个本地视频绝对路径 |
| `/current` | 在已有实例播放所给内容，不受多实例偏好设置影响 | 作为复用实例的首选参数，零实例行为仍须实测 |
| `/new` | 新开实例播放所给内容 | 不作为默认策略，避免制造会话歧义 |
| `/autoplay` | 播放上次项目 | 不追加；不能将其理解成“立即播放传入文件” |
| `/add`、`/insert` | 向播放列表追加／插入 | 不用于首版直接打开工作流 |
| 打开文件相关偏好 | 文件打开行为还受播放器配置影响 | 必须覆盖用户配置差异，启动成功不等于目标视频开始播放 |

本机注册表默认值实际包含外层引号及末尾空白，路径读取要先去除首尾空白，再解析路径外围引号，不能直接把原始注册表字符串交给 `QFileInfo`。不把注册表值当成任意命令执行。

首轮检查时没有运行中的 PotPlayer。可执行文件版本资源返回 `0,0,0,0`，首轮没有可靠确认播放器版本；上述说明文件证据仅证明文件及随附接口说明存在。后续实际播放与 SMTC 结果单列于第 10 节。

### Qt 与 Windows 官方接口

- Qt Quick 的 [DropArea](https://doc.qt.io/qt-6.11/qml-qtquick-droparea.html) 和 [DragEvent.urls](https://doc.qt.io/qt-6.11/qml-qtquick-dragevent.html) 可接收外部拖放文件 URL。QML 负责交互，实际文件校验与业务编排放在 C++。
- [QProcess](https://doc.qt.io/qt-6.11/qprocess.html) 支持独立的可执行文件路径与参数列表；使用绝对 EXE 路径避免隐式搜索，使用 `QStringList` 传视频路径，避免 shell 字符串拼接。脱离式进程启动结果只说明进程启动，不能确认视频载入。
- Windows [App Paths](https://learn.microsoft.com/en-us/windows/win32/shell/app-registration) 可提供安装版程序位置；显式保存的用户路径优先，不存在时必须提示重新选择，不能悄悄改用另一安装。
- [GlobalSystemMediaTransportControlsSession](https://learn.microsoft.com/en-us/uwp/api/windows.media.control.globalsystemmediatransportcontrolssession?view=winrt-26100) 提供来源应用 ID、媒体属性、时间轴和播放控制；该接口没有直接暴露视频完整路径或 PID 的成员。因此，启动进程的 PID、来源应用 ID、文件身份不能直接画等号。

## 3. 当前项目的复用点与缺口

| 位置 | 当前行为 | 所需改动 |
|---|---|---|
| `qml/Main.qml`、首页／播放页 | 尚无文件 DropArea | 主内容区统一接收视频拖入，首页／播放页提供打开视频动作；模态弹窗打开时停用该入口 |
| `src/infrastructure/SettingsStore.cpp` | `targetSession` 保存 SMTC 来源应用 ID；没有播放器程序路径 | 新增播放器类型及程序路径配置，明确与同步会话绑定的区别 |
| `src/application/AppController.cpp` | 负责选会话、切换模式、加载及展示 | 增加视频打开事务，串接启动、会话确认、自动来源提交和失败提示 |
| `src/platform/windows/MediaMonitor.cpp` | 约 100ms 基础轮询；会话列表每 10 轮发布；前台匹配含 EXE 名称回退 | 打开事务需要及时发现候选会话；名称匹配只能作为候选依据，不是完整路径或具体实例证明 |
| `src/platform/windows/SmtcReader.cpp` | 按来源应用 ID 采样；相同 ID 多会话时拒绝连接；控制使用 session token／代次／新鲜度 | 保留已有拒绝歧义和控制校验；不得因新入口而改为控制第一个同名会话 |
| `src/application/AutomaticDanmaku.cpp` | 600ms 稳定标题；关联／缓存优先；在线匹配及失败恢复 | 加入已确认打开上下文的文件名输入，与真实 SMTC 标题分开保存 |
| `src/application/AppController.cpp::start()` | 必须已有弹幕和渲染器；普通调用会暂停自动匹配 | 不能在刚启动播放器时直接调用；等待自动结果，沿用受保护的自动提交路径 |
| `src/application/AppController.cpp::onSample()` | 独立播放时不向自动匹配服务传采样 | 打开视频工作流须显式切回跟随模式并解除本次自动匹配暂停 |

现有自动加载成功后已会调用 `start(false)`，再按当前采样位置同步。主要工作是补齐其上游打开事务，并避免触发手动来源的“暂停自动匹配”路径。

## 4. 推荐交互

设置页增加“外部播放器”分组：类型默认 PotPlayer、程序路径、选择程序按钮及路径有效性提示。首次使用可从明确的注册表候选发现；候选不唯一时让用户选择并保存。便携版直接手选 EXE，不全盘扫描，不修改注册表或系统默认打开方式。

普通操作留在首页／播放页：提供“打开视频”按钮和“拖入视频，使用 PotPlayer 播放并匹配弹幕”的提示。拖动进入时显示轻量提示，成功后进入播放页，显示“正在启动播放器／等待视频就绪／正在匹配弹幕／已启用”等实际阶段。程序路径缺失时保留待打开文件，选择完成后继续，不要求重复拖入。

建议将拖入行为视为对本次自动匹配的明确操作，采用运行期的有效启用状态，不默默把持久化的 `automaticDanmaku=false` 改成 `true`。本次工作流可继续跟随后续切集；手动停止、卸载、选源、取消绑定或切换到其他播放器时撤销运行期启用。用户主动修改全局开关的操作应清除临时覆盖，并立即遵循新值。所有设置重配入口都必须使用同一有效状态，避免调整字号时意外关掉本次匹配。

UI 继续使用现有 Fluent 标准控件与卡片；新增长路径字段和错误提示应覆盖窄窗、键盘焦点、文字缩放以及现有滚动条留白规范。不要为拖放提示给透明弹幕层增加交互命中区域。

## 5. 打开事务与会话确认

建议顺序：

```text
接收单个文件
  → 校验视频与播放器路径
  → 建立新打开代次，取消旧匹配／恢复事务，清除旧弹幕
  → 暂停自动服务接收旧内容，记录原会话／标题／token
  → 启动或复用 PotPlayer
  → 等待唯一相关会话与目标视频的有效采样
  → 切换为跟随模式，提交本次文件名上下文
  → 复用关联／缓存／在线匹配
  → 成功后按当前媒体位置展示；失败进入现有恢复弹窗
```

建议由应用服务持有单调递增的 `openGeneration`，请求包含视频路径、文件名、播放器路径、启动时间、先前会话信息和取消状态。GUI 不忙等，不加入逐帧文件检查；使用现有采样和单个事务超时。可先以 15 秒作为待调优的会话等待上限，不将其描述为性能成绩。

会话确认必须同时考虑：

1. 来自预期 PotPlayer 的唯一候选；已有显式会话绑定不能静默跳到其他播放器。初次无法可靠识别来源 ID 时允许一次性手选绑定，不假设所有版本的来源 ID 都是固定 EXE 名。
2. 采样在本次打开之后获取、处于可用的 Playing／Paused 状态，时间轴有限且通过既有新鲜度校验。
3. 新媒体标题与拖入文件名相符，或者在唯一候选下有足够的番名＋明确集数一致性证据；单纯出现一个新进程、同一番名、相同来源 ID或时间位置归零都不足以证明目标视频已打开。
4. 新采样取得时间只能证明本次读取新鲜，不能证明播放器已经换文件。复用实例时，仍报告旧标题的采样不能开启匹配；重新选择相同来源 ID／刷新代次也不能代替内容确认。

SMTC 不提供完整文件路径，因此相同标题的不同文件、隐藏集数的媒体标签、同名多实例等情况不能保证全自动判定。首版应等待／提示确认，不能把弱关联当成精确文件身份。后续如果这类场景频繁，再独立评估 PotPlayer 专用路径／进度控制接口，不能直接引入网上流传的未核实消息常量。

## 6. 文件名解析与同步数据必须分开

拖入文件带来了比 SMTC 显示标题更完整的原始文件名，应在会话确认后将它用作本次识别输入，复用混合解析器。这能避免播放器只上报作品名或媒体标签导致集数丢失。

不要为了复用 `AutomaticDanmaku::observe()` 而把 `MediaSample.title` 改成文件名：现有播放控制会重读真实 SMTC 标题并比对，伪造标题会破坏失败恢复与暂停校验。

建议分别保存 `reportedTitle` 和 `recognitionFileName`，后者绑定本次打开代次与确认后的媒体身份。换文件、换会话、失联后无法确认原内容、手动选源或取消时使其失效。PotPlayer 自己切到下一集后改用新的媒体采样，不继续套用最初拖入的文件名；收到迟到的旧下载结果不得提交。

同名文件重复拖入也应有明确规则：确认仍是当前已打开文件且状态可复用时只展示当前状态；无法确认实际完整路径时，不据同名自动认定已打开或已完成切换。

## 7. 启动与生命周期

启动参数的初始验证方案为：

```cpp
// 示意，不是本轮已实现的接口。
process.setProgram(validatedAbsolutePlayerPath);
process.setArguments({validatedAbsoluteVideoPath, QStringLiteral("/current")});
process.setWorkingDirectory(validatedPlayerDirectory);
// 采用脱离式生命周期，返回后继续异步等待 SMTC。
```

- 是否使用 `/current` 覆盖零实例场景、不同“打开文件”偏好下是否直接播放，必须用当前实机版本验证。若无实例时需调整参数，由 PotPlayer 适配器决定，不暴露任意命令模板给用户。
- 不追加 `/autoplay`、`/seek=0`、`/new`，不强制改变续播位置、播放列表、多实例偏好或全屏状态。
- `startDetached`／启动成功只代表进程创建成功。复用已有实例时，新进程可能转交请求后退出；其退出不能当成播放器已关闭，返回 PID 不能作为实际播放实例身份。
- DanmaX 退出或取消匹配不终止 PotPlayer。新拖入可以取代旧事务，但不能强杀播放器；更换视频前清除旧弹幕，避免新旧内容叠加。
- 明确设置子进程环境；开发模式剔除仅供 DanmaX 使用的 Qt 插件搜索路径等覆盖，保持 TEMP/TMP 等可控缓存约束，不修改全局环境。PotPlayer 自己的用户配置与系统缓存位置属于外部应用行为，不承诺由 DanmaX 全部重定向。
- 路径由 `QUrl::toLocalFile()` 转换后校验存在、普通文件与允许类型；不手工 URL 解码，不执行 `.lnk`、脚本或拖入文本。只接受受支持的 Copy／Link 拖放动作，不接受 Move，打开视频不会移动或复制文件内容。
- 多个实例出现歧义时，在发出可能更换视频的启动命令之前提示；存在与既有绑定冲突的安装路径时也不静默复用未知实例。

## 8. 建议改动组织与验收

新增小型 Windows PotPlayer 适配器负责程序定位、候选识别与启动参数；新增应用层视频打开服务负责事务和状态。`AppController` 保持 UI 与已有自动服务的协调入口。只有实际出现第二种播放器适配器时再扩展通用能力，领域核心与渲染器无需加入播放器特例。

实施顺序建议先用已绑定的单个 PotPlayer 做真实接口验证，再实现路径绑定／打开事务、接入拖放与文件名上下文，最后覆盖已有工作流回归与部署目录运行。首先验证的阻断问题是“当前版本能否稳定提供目标视频的 SMTC 标题与时间轴”，而不是拖放 UI。

| 验证层 | 必须覆盖 |
|---|---|
| Qt Test／CTest | URL／路径转换，中文、空格、括号、`&` 等文件名；缺失／非文件／非法类型／多个文件；参数列表不拆分；绑定配置保存和失效提示 |
| 打开事务测试 | 未启动／已有实例；旧标题继续上报；无会话／超时；连续拖入 A、B 后 A 的旧结果不能提交；停止／手动选源／换绑定中断；相同标题不同文件与多实例拒绝歧义 |
| 自动匹配回归 | 运行期启用与全局开关的优先级；独立模式切跟随；命中关联／缓存；在线失败／歧义；已暂停保持暂停；文件名上下文不破坏真实 SMTC 标题控制校验；切集失效 |
| PotPlayer 实机 | 冷启动、复用、不同打开偏好、续播位置、视频切换与倍速／暂停／跳转、播放器 SMTC 不可用、退出及恢复；记录真实版本与来源 ID |
| UI 实机 | 资源管理器真实拖放、打开按钮／键盘替代、模态弹窗阻止误打开、长路径、窄窗／浅深色／放大文字／DPI、滚动区各留白和滑块交互；不同权限启动组合 |
| 覆盖层／部署 | 播放器全屏焦点、穿透、工具栏、跨屏、部署目录依赖与路径定位；独占全屏等既有边界仍按实测记录 |

## 11. 实施与当前验证范围

当前流程先切换并续订所选 PotPlayer 采样，读取启动前的原媒体状态，再发出参数列表打开命令；后续新鲜采样须与目标完整文件名或去扩展名文件名一致。原内容同名时需“使用当前视频”明确确认，过期采样不能使确认继续生效。启动期间禁用旧内容的自动匹配，确认后仅为本次工作流临时启用，继续复用原始 SMTC 标题及既有匹配／失败恢复接口；未另外伪造媒体标题或放宽弱文件名关联。停止保留已加载来源，打开新视频清除旧弹幕。
