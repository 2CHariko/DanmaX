# 公共定位事务

定位由应用层唯一 SeekController 编排，底栏定位和恢复观看进度共享该服务；播放器后端只提交命令、报告结果和采样。独立弹幕仍使用本地时钟，不进入媒体定位事务。

## 反馈和确认

后端通过 SeekDispatch 报告请求 ID、发送前的新鲜时间轴、实际发送／返回单调时间以及结果：

| 结果 | 语义 | 公共层行为 |
| --- | --- | --- |
| Rejected | 校验拒绝、目标无效或播放器明确拒绝 | 结束对应请求并显示具体原因 |
| Submitted | 消息或接口接受请求，尚不证明到达目标 | 等待发送后的新鲜位置读回 |
| Unknown | 消息超时／响应无效，可能已经执行 | 保持等待，不盲目重发 |

原始 seekFinished 仅是底层传输确认和测试注入端口，不能作为产品定位成功事件；产品只消费 SeekController 的 landed／finished。绑定、内容、代次与采样新鲜度继续校验，旧请求回调不影响新任务。

确认排除发送前采样及未变化的旧位置，使用实际发送时序约束播放推进，不能把 GUI 请求前排队和解码耗时全部算作正常播放时间。已声明 Precise 的接口要求目标范围读回；Unspecified 接口允许在观测到位置跳变及稳定后的新轨迹时报告实际落点，不能把任意较大误差包装成精确到达。弹幕始终以实际时间轴重置，不以预览位置驱动。

PotPlayer 查询消息仍有 100ms 上限；定位单独采用 500ms 的工作线程消息上限，超时且实例仍有效时报告 Unknown。VLC 保留 URI／播放列表项的服务端检查；传输失败／响应无效报告 Unknown，明确拒绝报告 Rejected，正常响应后也要读回。VLC 的公开时间接口按精确定位策略确认；PotPlayer 未验证当前定位精度，按 Unspecified 报告实际落点。

## 连续输入与超时

每次最多一条在执行请求和一条最新待执行意图。连续拖动替换尚未发送的意图，已发送请求未确认前不并发提交下一次定位。当前请求确认后，以最新时间轴提交最终目标；旧目标及其回调不覆盖最新预览。

默认确认窗口为 8 秒。到期仍未确认时提示结果未知，不自动重发，也不自动推进待执行意图；保留最多一条额外 8 秒的迟到观察记录。若同一请求后来确认完成，只清除该请求的提示；新请求、内容交接或结束取消旧观察。停止、实例退出及可靠内容变化清理全部状态。

没有播放器命令 ID 回显的协议无法保证辨认所有播放器外部并发定位，也不能撤销已经进入播放器的命令；实际落点反馈不是任意格式精确定位或无条件“恰好一次执行”的承诺。用户明确发起的新操作与未知命令的后续执行仍受播放器协议边界限制。

## 界面

鼠标拖动只预览，松手提交缓存的草稿目标；不能在释放后重新读取可能已被位置绑定覆盖的 value。定位等待期间保留最新目标预览，仍允许继续选择新目标，实际播放位置单独来自播放器。独立弹幕工具栏的定位也缓存草稿目标。定位状态与错误按请求关联，确认后结束等待；近似落点短暂显示实际时间，不以连接变化警告代替定位结果。

## 验证要求

覆盖消息超时但实际执行、异步回执先后顺序、旧缓存位置、精确与未知精度、迟到完成、连续目标合并、任务取消和历史恢复。Win32 延迟夹具仅验证 IPC 和请求次数，不替代真实解码。真实播放器应覆盖长 MKV／MP4、大跨度前后跳、播放与暂停、连续拖动、网络／映射路径及界面释放后目标不回弹；仅记录实际完成的验收范围。
