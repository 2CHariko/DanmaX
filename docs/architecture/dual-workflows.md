# 双任务工作流（视频同步与独立弹幕）

DanmaX 产品层支持**视频同步**与**独立弹幕**两种互斥任务。本文档说明两类任务的生命周期边界、续播条件及历史数据保存策略。

> [!IMPORTANT]
> 产品中所有弹幕来源操作（加载 XML、在线搜索、选择缓存）均作用于当前明确选择的任务。无任务时不隐式启动独立播放；内部合成时钟端口与测试驱动严禁暴露给 QML 界面。

## 1. 任务职责与互斥交接

| 组件 | 职责范围 |
|---|---|
| `MediaSession` | 管理本地视频打开、受控播放器实例建立、自动弹幕匹配、历史续播与视频来源 |
| `DanmakuSession` | 管理独立 XML / 在线分集 / 缓存弹幕的准备、加载、取消及本地单调时钟任务 |
| `PlaybackCoordinator` | 协调两类任务的互斥交接；切换后立即使旧异步加载、匹配、控制与弹窗全部失效 |
| `NowPlayingModel` | 按当前任务所有者向 QML 投影播放状态、元数据与可用操作能力 |
| `AppController` | 持有全应用唯一的弹幕引擎、单一帧驱动与弹幕覆盖层 |

### 关键流转规则

- **独立弹幕入口**：仅通过 **更多 → 独立播放弹幕 XML**（或播放页空闲入口）显式触发。先在后台异步解析 XML，确认有效弹幕后才切换任务并从零开始播放；取消、文件损坏或无有效记录时保留原任务继续运行。
- **独立任务换源**：在已有独立任务中更换弹幕来源时，准备期间原弹幕继续播放，交接后保留当前播放进度与暂停状态。
- **独立模式边界**：独立流程不依赖播放器进程、不轮询媒体状态、不自动识别文件名；播放/暂停与进度拖动仅控制本地弹幕时钟。
- **取消与失效**：结束或切换任务时立即取消旧请求、作废当前绑定文件对话框并关闭所属选源弹窗，迟到结果不得干扰新任务。

## 2. 继续观看与进度恢复

仅当历史记录满足 `5 <= position < duration - 10` 秒时提供“继续观看”语义；普通重新打开同一视频也会自动应用有效历史进度，选择“从头播放”则请求定位到 `0`。

视频任务打开顺序严格为：
1. 验证视频文件与外部播放器程序；
2. 启动并校验本次受控播放器实例；
3. 确认目标媒体身份；
4. 通过 [公共定位事务](seek-transactions.md) 恢复历史位置（默认确认窗口 8 秒）；
5. 启动弹幕自动匹配与准备流程。

定位传输超时时不会盲目重发，恢复失败时保留原历史进度，允许用户重试或按当前位置继续。

## 3. 最近记录与关联存储

- **最近视频（`recent-videos.json`）**：格式版本 `1`，使用 `QSaveFile` 原子写入，上限 `100` 条记录且文件不超过 `8 MiB`。按规范化视频路径去重，保存进度、时长、文件指纹、弹幕来源引用与元信息；**严禁保存进程 PID、端口或认证密码**。仅在确认视频后写入记录，播放期间每 5 秒及暂停/退出时补写。文件指纹变更会使旧进度、来源与元信息失效。
- **匹配关联（`media/media-associations.json`）**：格式版本 `1`，上限 `512` 条、`512 KiB`。用于精确复用已确认视频标题或番名/分集对应关系。
- **任务结束与实例关闭**：
  - 更换或卸载弹幕仅影响弹幕层，保留当前视频连接。
  - 结束视频任务、明确交接至独立任务、取消启动或应用退出时，仅请求正常关闭本次由 DanmaX 启动并核实身份（PID、创建时间、程序路径）的受控播放器；关闭失败报告真实状态，严禁强杀进程或接管普通发现实例。
  - 历史无效旧配置（外部会话连接、手填应用 ID、旧独立模式开关）继续忽略，原有 XML 路径、缓存、最近记录、主题与样式保留。

> [!NOTE]
> 当 `recent-videos.json` 损坏时，应用保留原文件内容并在写入失败时向用户报告错误；视频文件缺失的记录仍保留在列表中允许手动移除，不会自动删除本地视频或 XML 文件。
