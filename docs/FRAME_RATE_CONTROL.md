# 弹幕帧率控制

## 设置与语义

`[Rendering]` 增加三个字段，旧的 formatVersion=1 配置缺失字段时使用默认值，无需迁移：

| 字段 | 默认值 | 范围与作用 |
|---|---|---|
| frameRateLimit | 60 | 0 跟随显示器，或整数 15～1000；限制连续动画刷新请求 |
| adaptiveFrameRateEnabled | false | 开启后按呈现反馈调整新弹幕入场额度 |
| targetFrameRate | 60 | 整数 15～1000；流畅度要求，独立于刷新上限 |

上限 120、目标 60 时，呈现 90 Hz 已满足目标，不需要减量。有效目标受上限和覆盖窗当前显示器的近似刷新率限制；保存用户原值，运行状态解释限制原因。刷新率未知时显示未知，不假造显示器能力。设置即时生效，延续 200ms 合并写盘。

## 帧请求与时间轴

标准库 `FramePacer` 保存绝对单调截止时间；晚到的帧跳过已经错过的时间槽，不追帧，也不把渲染耗时叠加到下一次等待。GUI 线程单个 QChronoTimer 只请求窗口刷新，可见动画仍在 afterAnimating 中按实际时间推进。帧请求前标记文字项需要同步，回调内替换快照时不重复请求，避免软件渲染追加不变帧。

下一帧在当前帧准备阶段安排，不等待 GUI 排队接收 frameSwapped。Windows 原生后端请求在当前平台事件返回后发出，避免 Qt 初始计时器转为 DXGI 回调时同时保留两种请求。跟随显示器以及上限不低于已知显示器刷新率时使用原生节奏；更低上限依据实测平台请求交付延迟提前安排请求，afterAnimating 仍检查绝对截止，提前请求不提前推进动画。取消、暂停和重新配置使尚未发出的旧请求失效。

媒体采样、窗口呈现和无帧维护共用请求调度器；暂停、隐藏、停止撤销连续请求。恢复、跳转、媒体切换和外观修改保留必要的单次刷新。因此它是连续动画的上限，不是禁止窗口系统重绘的硬上限。暂停不计入寿命，限帧不改变滚动速度或媒体倍速。

覆盖窗的公开 QEvent::UpdateRequest 也经过额度检查，阻止 Qt 共享动画驱动器因其他窗口动画而提前刷新覆盖窗。暂停时只放行待处理的单次刷新和脏快照；窗口暴露、平台表面与计时器事件不拦截，不访问 Qt 私有 API。

QScreen 刷新率只作能力提示，不能当作定时器动画时钟。实际 60 Hz 请求在 144/165 Hz 显示器上可能交替使用不同垂直刷新间隔，需要同时观察长窗口平均值和帧间隔。

## 自适应入场

- 额度从用户最大在屏数量开始，最低为其四分之一向上取整；不会调整资源池容量或清除已有弹幕。
- 每个完整的一秒窗口统计呈现回调频率。连续两个窗口低于有效目标的 90%，额度减少当前值的 10%，向上取整；连续五个窗口达到目标的 97%，额度增加用户容量的 5%，向上取整；每次至少变化 1。
- 降额后若在屏数量仍高于额度，状态为“正在减负”，等待自然退场，不连续降额。到达底线仍持续不足时报告目标未达成。
- 滚动、顶部和底部按源时间顺序共用额度。超过额度时先跳过再测量文字，单独统计 adaptiveSkipped；不缓冲、不迟到补发。
- 暂停、隐藏、弹幕关闭、空屏不参与反馈；恢复后的前两秒预热。播放开始、跳转、媒体切换、显示器、DPR 或渲染配置变化重置反馈。暂停保留临时额度，新的播放或配置重置从完整额度开始。
- 关闭自适应立即恢复完整入场容量。字体、描边、图片精度、缓存预算不由该策略改变。临时额度不写入 INI。

## 诊断与复现

设置页及 HUD 展示有效上限、有效目标、当前额度、呈现频率、呈现间隔 P95 和策略状态。报告增加 adaptiveSkipped、admissionFloor、adaptiveWindowHz、frameLimitWaitMs、sceneGraphUpdateMeanMs 和最多 360 个逐秒 frameRateSamples。

呈现指标来自覆盖窗 frameSwapped 发出时的单调时间戳。回调只写入独立持有、线程安全、最多 4096 项的队列；GUI 批量读取并执行自适应策略，渲染线程不访问控制器、QML 或设置。presentationSamplesLost 记录缓冲区溢出；溢出后重启反馈预热，避免用缺失样本误减量。关闭自适应时不逐帧计算策略或更新诊断设置表。它是呈现提交回调代理，不是光学 FPS 或 GPU 执行时间；旧版 GUI 排队时间戳的 P95 不可直接与新版比较。sceneGraphUpdateMeanMs 只测量 updatePaintNode 的 CPU 工作，不代表整条 GPU 渲染链。限帧等待、引擎与快照工作分别记录。原有 p95Ms/p99Ms 仍是 GUI 推进间隔。

文字纹理准备按经过时间补充额度：基础 CPU 每秒 120ms、上传每秒 240MiB；已知有效上限高于 60 时按原有每帧 2ms / 4MiB 的能力提高补充速率。初始 2ms / 4MiB，最多积累 8ms / 16MiB；单条上传仍限 4MiB。实际帧间隔的平滑均值在有效上限周期的 110% 内时，才扩展较低上限下的单帧额度；过载、初始帧或长暂停后维持单帧 2ms / 4MiB，避免加重卡顿。一次不可中断的文字栅格化可能超支，之后偿还额度。额外回调不补充额度，暂停后不积累无界突发；缓存容量、文字清晰度和描边保持原设置。

稳定快照复用文字引用，只有 ID、布局或颜色变化时替换；移动仍按实际时间更新坐标。全部活动文字已转为图片缓存时，固定弹幕避免重复提交相同变换矩阵；含文字回退或仍在转换的场景保留原变换更新方式，避免 Qt 静态文字批次重建的性能回归。

```powershell
./scripts/build.ps1 -Preset windows-static-release -Test
./scripts/validate-frame-rates.ps1
./scripts/validate-frame-rates.ps1 -Preset windows-debug -SkipStress
./scripts/validate-frame-rates.ps1 -Limits 60 -SkipStress -ScaleFactor 2
./scripts/validate-frame-rates.ps1 -Limits @() -StressBackend text
```

验证脚本从自身位置定位项目，使用锁定工具链、原生 D3D11/threaded 和独立产物目录，生成离线 XML，记录硬件与二进制哈希。支持 Debug、动态及静态 Release；每轮必须正常退出，超时保存输出并判失败，生成报告不能替代退出检查。低负载默认测试 30/60/120/47/跟随显示器，每轮 15 秒，剔除前三秒后要求完整采样时间至少 10 秒且平均频率在有效上限 ±5% 内。压力组在同一 XML 上对照自适应关闭与开启；保留未达标结果，不能把仅生成报告当作性能达标。

旧的渲染器/图片预算对比脚本显式设置 frameRateLimit=0，以保持其比较渲染吞吐的目的。硬件、构建、文字、分辨率、DPR、后台视频和温度都可能影响结果；首版实测见 [FRAME_RATE_PERFORMANCE_20261014.md](FRAME_RATE_PERFORMANCE_20261014.md)，后续 165 Hz / Debug 优化复测见 [FRAME_RATE_OPTIMIZATION_20261014.md](FRAME_RATE_OPTIMIZATION_20261014.md)，实现与待验收边界见 [FRAMEWORK_STATUS.md](FRAMEWORK_STATUS.md)。
