# 帧率控制优化与复测（2026-10-14）

本轮修正帧请求路径及逐帧开销。低负载限帧在报告 165.002 Hz 的屏幕上达标，普通文字场景降低 CPU 工作；不能据此承诺 Debug 高密度长文字达到目标。指标是 Qt 呈现回调代理，不是光学 FPS 或 GPU 时间。

## 改动

- 下一帧在 afterAnimating 准备当前帧时安排，不等待 GUI 排队接收呈现回调。Windows 请求在当前平台事件返回后发出，避免新增原生测试发现的 Qt 初始计时器 / DXGI 交接断言。跟随显示器及上限不低于显示器能力时使用原生节奏；低于显示器的上限按实测交付延迟提前请求，实际动画仍检查绝对截止。
- 取消、暂停和配置变化使未发出的旧请求失效；暂停中的外观、帧策略和 HUD 设置保留单次刷新。维护检查及共享动画驱动的刷新经过同一门控。
- 呈现回调只将发出时的单调时间戳写入独立持有、线程安全的有界缓冲区。GUI 批量读取；关闭自适应时不逐帧写策略诊断。溢出报告丢失数量，并重启反馈预热。
- 热路径使用 const 查询读取设置，消除临时 QMap 上非 const operator[] 导致的整表复制。稳定文字快照复用布局引用；ID、布局和颜色变化仍替换引用。
- 全部文字已有图片缓存时，固定弹幕不重复提交相同矩阵；滚动坐标变化照常提交。部分缓存和 Qt 文字回退保留既有变换更新方式。
- 纹理准备按经过时间补充额度，只有实际帧节奏有余量时才扩大低上限下的单帧额度。过载、初始化和长暂停后保留原单帧 2ms / 4MiB；容量、字体、描边和图片精度保持用户设置。

细节及字段见 [FRAME_RATE_CONTROL.md](FRAME_RATE_CONTROL.md)。没有新增依赖或专用 GPU 测量后端。

## 环境与方法

Windows 11 x64、Qt 6.11.0、Debug、D3D11/threaded，2560×1440 逻辑尺寸、DPR 1、覆盖窗报告 165.002 Hz。CPU AMD Ryzen 5 5600，12 逻辑处理器；系统枚举 RTX 4070（32.0.16.1692）及 GameViewer、Zako、MuMu 虚拟适配器。未用 GPU 专用测量确认活动适配器或光学刷新率。

优化前是加入帧率控制、尚未进行本轮优化的同一 Debug 构建，SHA-256 `167F215CF6398D7CE561CE8F71F0DD01904CF8F5EC10EB35B7E9D5466C7864D8`。最终 Debug SHA-256 `E2E348D8A9347792DCC10D99DE2C0F83125BA5752F06889B0B20BDB04D538A99`。各轮隔离设置、缓存与 XML；不修改开发者运行配置。CPU 按全部逻辑处理器归一。

剔除起始前三秒，要求每个采样窗口整体位于预热之后；低负载每轮 15 秒、统计约 11 秒。呈现间隔 P95 表中为各完整窗口 P95 的平均值，不是合并后的全程 P95。旧版 GUI 排队时间戳与新版发出线程时间戳的呈现 P95 不可直接比较。

## 排除的方案与边界

- 无条件扩展纹理准备到 8ms 的试验在重载末段从约 15.5 降至约 14.4 Hz，未采用。最终只有节奏有余量时扩展额度。
- 对所有固定节点跳过矩阵提交的试验在大量文字回退、持续转换时从约 15 降至约 5 Hz，未采用。依据 Qt 批次更新实现，推断与静态文字批次的重建有关；最终限定为全部图片缓存后启用，并重测重载恢复约 14 Hz。
- 这两项失败证据分别保存在 `trial-unconditional-budget/` 和 `trial-all-transforms/`，不能当作最终性能结果。
- 还没有完成真实视频背景、144 Hz、跨屏混合 DPI、温度 / 功耗、光学或 GPU 执行时间测量。实际显示器 / 播放器组合仍可能有差异。
