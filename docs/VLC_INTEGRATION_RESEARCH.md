# VLC 外部播放器接入调研

日期：2026-10-17。范围为 Windows 桌面版 VLC 与当前 C++20／Qt Quick 工程。以下保留实施前调研和独立探针，正式接入进展见末尾“实施结果”。没有修改 VLC 安装或用户配置。

## 结论

VLC 可以接入，SMTC 不是必要条件。建议采用“VLC 预设＋官方 Lua HTTP 接口＋项目自带的小型精确状态端点”，并把现有媒体采样／控制抽象为可替换后端；PotPlayer 继续使用 SMTC。只增加 `vlc.exe` 启动适配器无法完成同步，目前空 sessionId 在 VideoOpenService 中明确表示仅打开文件。

用户当前普通启动的 VLC 没有开放控制端口，不能仅凭 EXE 路径可靠读取该实例的播放进度。产品必须区分“DanmaX 启动的受控实例”和“用户已启动但没有控制接口的实例”；不能假定把启动参数传给第二个进程便能给既有实例补上控制接口。

## 本机观察

- 运行程序元数据为 VLC 3.0.23，PE Machine 0x8664（x64），可从运行进程和 HKLM App Paths 定位 EXE。
- 当前原实例命令行只有程序路径，窗口标题为 VLC media player；未发现该 PID 的 TCP 监听端口，安装插件目录未发现 SMTC 插件。
- 使用 Windows GSMTC API 枚举，当前返回空会话列表。原实例当时未显示播放文件，不能仅凭这个快照推断所有 VLC 版本或所有播放状态都不支持 SMTC。
- 有第三方 SMTC 集成插件，需要匹配 VLC 架构、安装 DLL、启用控制接口并重启。调研时实时项目 README 声明支持 3.0.x 和 4.0.0-dev nightly；搜索引擎旧摘要仍声称不支持 VLC 4，应以实际版本与实时说明为准。本轮未安装或验证该插件。

## 方案比较

| 方案 | 优点 | 边界与判断 |
| --- | --- | --- |
| 第三方 SMTC 插件 | 可最大限度复用现有 SMTC 工作流 | 需安装／启用／重启及版本架构匹配；还须实测标题、时间轴和实例身份。可选兼容途径，不作为默认依赖 |
| 内置 HTTP 接口 | 结构化状态、URI／播放列表、明确暂停／恢复和倍速控制；可用现有 Qt Network | 默认未启用；标准时间字段取整，推荐增加小型精确状态端点并由程序管理启动参数 |
| RC／Lua CLI | 无需新增第三方库，可读状态和发送控制命令 | 常用 get_time/get_length 同样返回整数秒，文本响应关联及 pause 切换语义不适合作为首选同步协议 |

不需要用户填写端口、密码、JSON 参数或 SMTC 来源 ID。界面仍保留预设、EXE 路径、发现／选择及连接状态，连接细节由适配器管理。

## 独立探针结果

使用已有 VLC EXE 创建独立临时实例，显式禁用单实例转发，采用 dummy 界面和音频输出。仅播放项目产物目录生成的 **60.5 秒静音 WAV**，包括中文、空格和 `% & #` 文件名。没有切换用户原 VLC 内容，未安装插件、改写用户配置或新增系统依赖。临时实例、Lua 页面和可控制缓存均位于项目 `out/validation/vlc-research/`；测试结束只关闭本探针拥有的进程，原 VLC PID 保持不变。

官方 HTTP 模块通过 `--http-src` 载入项目目录的自有页面；页面复用现有 VLC Lua 接口读取 input time、item duration 和 URI，保留官方状态及控制命令。只监听 127.0.0.1，使用临时随机认证密码；实测监听 PID 与探针一致。密码不写入报告。

| 项目 | 观测结果 |
| --- | --- |
| 标准 time | 0、0、0、0、1……，整数秒 |
| 精确 time | 0.300、0.550、0.804、0.804、1.101……秒 |
| 标准／精确 duration | 60／60.5 秒 |
| 暂停 | forcepause 后状态 paused；间隔 250ms 再读位置变化 0 秒 |
| 跳转 | 暂停状态请求 seek=10，读到 10 秒 |
| 倍速与恢复 | 请求 1.5 倍，实际读到约 1.50150156，状态 playing；应使用实际倍率 |
| 文件身份 | URI 与提交的完整文件 URI 一致，包含中文及特殊字符；可取 currentplid |
| 本次 8 次状态请求 RTT | 22.41–24.99ms，均值 23.48ms；仅此短探针，不是性能承诺 |

注意：小数秒字段只说明数值没有被取整，并非逐毫秒更新。探针中位置会重复，更新间隔可达约 250–300ms；正式视频的输入时钟刷新、请求延迟和暂停／跳转时序还须测量。不能把服务器响应时间当成其 input 位置必然刚刚更新的证明。

标准 HTTP position 虽为小数，但乘以被取整的 length 会引入比例误差，不能直接宣称精确同步。首选读取原始 time／精确 duration，结合单调时钟估计连续播放；暂停冻结，跳转、切片、失联和变速触发必要的重置。

证据：`out/validation/vlc-research/http-probe.json`、`smtc-sessions.json`、`probe-http.ps1`、`http/status.json`。上述静音探针不代表用户视频的图像验收；后续真实视频专项见下节。VLC 弹幕覆盖、全屏、切集或长时漂移仍未验收。

## 用户视频调用验证（2026-10-17）

在用户追加授权后，使用此前提供的 KitaujiSub 第 1 集 MP4，启动独立的 VLC Qt 图形界面实例，加载同一回环 HTTP＋精确状态页面，通过 in_play 提交真实文件 URI。原 VLC 实例保留，未改写安装文件或用户配置。

- 完整 URI 匹配，实际播放状态 playing，位置连续推进；时长 **1420.086 秒**。
- 视频流为 **HEVC/H.265，1920×1080，23.976024 fps**；音轨 AAC。初始专项结束已解码 268 帧视频、显示 71 帧、解码 581 个音频块；使用 dummy 音频输出静音，未验收扬声器实际出声。
- 明确暂停后间隔 300ms 位置变化 **0 秒**。请求跳转到 30 秒，恢复播放约 900ms 后读取 **30.643999 秒**。
- 请求 1.5 倍，实际读取 **1.50150156**；结束恢复实际 **1 倍速**播放。
- VLC 内部快照首次为纯黑图，未作为有效画面证据；追加跳转到 60 秒，取得 `vlc-frame-00002.png`，1920×1080，像素采样亮度有明显变化，已目视确认实际动画画面。该图是播放器解码快照，不是桌面窗口／全屏合成验收。
- 在实际视频 playing 期间重新枚举 GSMTC，出现其他应用会话，**仍无 VLC 会话**。支持此版本／配置确实需要独立媒体通道的判断，不扩大到所有 VLC 版本。
- 测试实例保持图形界面和静音 1 倍速播放，便于用户直接查看；用户原先的空闲 VLC 实例保持不变。临时接口只绑定回环地址，凭据未写入报告，关闭测试实例即可结束该接口。

证据位于 `out/validation/vlc-research/real-video/`：`result.json`、`followup-status.json`、`smtc-while-playing.json`、`vlc-frame-00002.png`；调用脚本为其上级 `probe-real-video.ps1`。本轮验证真实 VLC 播放和控制，尚未把 VLC 接入 DanmaX 正式预设、自动匹配或弹幕渲染。

## 当前工程需要调整的部分

1. **媒体后端端口**：在基础设施／应用层增加统一的连接、采样、明确暂停／恢复及断开接口，提供 SmtcBackend 与 VlcHttpBackend。MediaSample 已有位置、时长、倍率、播放状态、代次和新鲜度，可复用其大部分结构；补充提供者、实例身份与媒体 URI，领域核心和轨道渲染不依赖具体协议。
2. **启动结果与实例绑定**：启动返回 PID／进程启动身份及连接描述，不只返回错误字符串。端口必须核对所属 PID，并处理占用／失败重试；随机密码不进入日志。只在回环地址监听，请求有大小、超时、并发上限，最多一个状态请求在途。控制端点、Lua 资源与协议版本由程序管理。
3. **打开事务**：当前服务先等 SMTC 原媒体基线再发启动命令。VLC 控制端口在启动后才出现，需要先启动／连接受控实例、读基线，再发打开 URI 命令并确认目标就绪，避免等待不存在的 SMTC 会话而死锁。已有受控实例通过接口打开新文件；普通未受控实例不静默接管。
4. **内容确认**：VLC 使用规范化 URI＋实例／播放列表身份核实目标，优于只比较窗口标题。同名文件、路径编码、同项重放和切集仍有独立边界；不能因此放宽 PotPlayer 的同名确认保护。
5. **控制与前台匹配**：PlaybackRecovery 已通过控制请求／结果信号隔离传输，可复用事务；VLC 使用明确 forcepause／forceresume，先核实预期实例与内容，收到同内容暂停确认才拥有恢复资格。前台窗口按实际 PID／窗口归属匹配，不能让任意 vlc.exe 窗口成为当前绑定实例。
6. **采样与生命周期**：建议从约 100–200ms 有界异步采样开始实测，不以轮询频率宣称输入时钟精度。迟到响应、切换播放器、内容变化、退出和重连都受代次保护；退出 DanmaX 时只断开自有连接，不默认关闭用户播放器。

这是媒体基础设施的一次中等改动，不能只注册一个新 preset 然后视为完成。建议先以独立后端证明真实视频的播放／暂停／跳转／变速和 URI 身份，再接自动匹配、暂停恢复及全屏覆盖层，最后提供正式预设。

## 实施结果（2026-10-17）

已注册 VLC 3.x x64 预设，保留自动发现和手动路径验证，新增 `MediaPlaybackBackend`、`SmtcBackend`、`VlcHttpBackend`。通过项目自有 Lua 状态端点同步受控 VLC，界面不暴露连接参数。端口归属、PID 创建时间、请求代次、URI 和播放列表项共同保护连接及控制；暂停／恢复在服务器端再次核对媒体身份。未增加第三方依赖，未修改领域时间轴或渲染器。

正式 Release 集成使用用户提供的第 1 集视频：自动发现真实 VLC、完整 URI 确认、时长 1420.086 秒、自动载入 2760 条弹幕，实际文字像素和独立覆盖窗口可见性通过。随后真实暂停冻结、恢复及同一受控实例重新打开同一文件通过，3 passed、0 failed。证据：`out/vlc-real-release-final.txt`、`out/validation/vlc-integration/release-real-final/`；`overlay.png` 已目视检查，是独立弹幕图像，不是桌面视频合成截图。测试结束仅关闭自身建立的实例。

首次联调发现切换播放器时旧绑定重置提前清掉待打开视频，已调整绑定／重置顺序后重新通过。协议专项覆盖特殊字符 URI、精确时间、身份改变、迟到响应、错误端口归属、超限响应和过期控制。完整构建与 UI 回归结果统一记录在 [FRAMEWORK_STATUS.md](FRAMEWORK_STATUS.md)。

尚未验收：VLC 4、缺失 Lua HTTP 的精简安装、长时漂移、全屏／多显示器混合 DPI 和桌面视频合成。既有普通 VLC 实例不自动接管；退出 DanmaX 只断开连接，后续重新打开建立新受控实例。
