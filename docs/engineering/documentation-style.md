# DanmaX 文档撰写规范（Microsoft 简体中文技术文档标准）

本规范定义 DanmaX 项目所有文档的结构、语言风格、排版细节、状态标记与索引维护要求。所有新增与更新的 Markdown 文档均须遵循本规范。

> [!IMPORTANT]
> 本项目默认第一语言为**简体中文**。除外部协议专有名词、命令行参数、代码标识符与原始报错外，正文、标题、表格与提示均应使用规范简体中文编写。

## 1. 语言与文风原则

参考 Microsoft 简体中文技术文档本地化与写作指南（Microsoft Writing Style Guide）：

1. **第二人称与祈使句**：面对操作者时使用“你”（不使用“您”），操作步骤使用直接祈使句（例如“运行以下脚本”而不是“建议用户可以通过运行脚本来……”）。
2. **客观与可验证**：陈述架构、性能与能力时基于可复现事实。禁止使用“丝滑”“完美”“极致”“颠覆”等主观修饰词。
3. **术语一致**：全仓使用统一中文术语，避免同义词混用。核心术语对照见下表。
4. **状态边界明确**：每份涉及功能实现、打包或性能的文档必须严格区分以下状态：
   - **已验证**：存在已记录的测试命令、运行环境与产物证据。
   - **已实现未验证**：代码已合入，但尚未在目标环境完成实机或专项验收。
   - **计划中**：设计或规划阶段，尚未合入代码。
   - **调研/历史基线**：早期可行性评估、一次性探针或已归档的阶段记录。

### 核心术语对照表

| 术语 | 规范写法 | 避免混用 |
|---|---|---|
| 弹幕显示窗口 | 弹幕覆盖层（或“覆盖层”） | 弹幕遮罩、弹幕浮皮 |
| 主程序面板 | 主控制面板 | 控制台窗口、管理后台 |
| 顶部悬浮条 | 快捷悬浮工具栏 | 吸顶条、顶部条 |
| 播放器进度跳转 | 定位（Seek） | 拖动条跳转、空降 |
| 受控外部播放器 | 受控实例（或“拥有实例”） | 接管播放器、托管进程 |
| 独立弹幕模式 | 独立弹幕任务 | 脱机模式、纯弹幕模式 |

## 2. 文档标准结构

每篇正文文档应遵循以下标准章节结构：

1. **唯一 H1 标题**（`# 文档标题`）：明确概括文档主题。
2. **导语与适用范围**：1–3 句说明本文档的目标读者、适用场景与前置条件。
3. **状态或警示提示块**：使用 GitHub / Microsoft Learn 标准 Alert 语法：
   - `> [!NOTE]`：补充背景信息或设计边界。
   - `> [!IMPORTANT]`：关键前置条件或不可忽略的约束。
   - `> [!WARNING]`：可能导致配置损坏、数据丢失或行为失效的风险操作。
   - `> [!CAUTION]`：高危操作后果警示。
   - `> [!TIP]`：常用最佳实践或快捷路径。
4. **正文小节**（`##`、`###`）：按“概念 / 架构 -> 规则 / 接口 -> 操作步骤 -> 验证边界”顺序组织，避免平铺流水账。
5. **相关内容**：文末统一提供关联文档的相对路径链接，形成网状可导航结构。

## 3. 排版与格式约定

- **中英文与数字空格**：中文与半角英文字母、数字之间保留一个半角空格（例如 `Qt 6.11`、`C++20`、`16 px`、`34 MiB`）；全角中文标点（`，。：；（）`）前后不加多余空格。
- **专有名词大小写**：保持官方标准拼写，例如 `DanmaX`、`Windows 11`、`FluentWinUI3`、`QWindowKit`、`libVLC`、`PotPlayer`、`VLC`、`CTest`、`CMake`。
- **行内代码**：文件路径、命令、参数、配置键、类型与方法名使用反引号包裹，例如 `` `docs/README.md` ``、`` `scripts/build.ps1` ``。
- **代码块**：始终标明语言标识（如 `powershell`、`json`、`ini`、`cpp`、`text`）。
- **文件命名**：除总索引 `README.md`、根目录规范文档（`AGENTS.md`、`CONTRIBUTING.md`、`DISCLAIMER.md`）与 `settings.example.ini` 外，所有专题文档统一采用**小写 kebab-case** 命名（例如 `cpp-qt-architecture.md`）。

## 4. 分类存储与索引维护规则

- 所有文档必须归入 `docs/` 下的对应职能子目录（`user/`、`architecture/`、`playback/`、`ui/`、`engineering/`、`release/`、`status/`、`research/`），禁止在 `docs/` 根目录堆放新的零散文档。
- 新增、重命名或归档文档时，必须同步更新 [`docs/README.md`](../README.md) 中的分类索引表与状态标签。
- 状态变更流水不得无限追加至单一文件；按月归档到 `docs/status/changelog-YYYY-MM.md`，并保持 `docs/status/current-status.md` 只反映当前最新验收状态与已知问题。
