# 外部播放器预设与公共后端契约

本文档定义 DanmaX 外部播放器的预设发现、可执行文件验证、配置持久化，以及所有播放器后端共用的 `MediaPlaybackBackend` 生命周期与媒体证据契约。

> [!NOTE]
> 包含 libVLC 的开发构建另提供内置播放器预设（`libvlc`），不要求外部程序路径；未启用该特性的发布构建保留该选项但明确显示不可用，详见 [内置播放页接入](libvlc-integration.md)。

## 1. 预设管理与路径验证

当前正式支持 **PotPlayer x64** 与 **VLC 3.x x64** 两个外部播放器预设。你可以在 **设置 → 外部播放器 → 管理播放器** 中选择默认预设、触发自动发现、使用系统原生文件对话框选择或直接输入路径。名称、启动参数与同步协议由适配器硬编码维护，不提供自定义增删入口。

### 1.1 自动发现策略

- 仅从 Windows 注册表 `HKCU` / `HKLM` 的 `App Paths`（含 `WOW6432Node`）读取安装记录，**禁止全盘扫描或依赖隐式 `PATH`**。
- 候选路径先执行兼容校验并按规范化路径去重：仅发现 1 个有效路径时自动填入草稿；发现多个有效路径时列出候选供你选择；打开视频仅接受唯一有效路径。已保存路径失效时明确报错，不静默替换。

### 1.2 PE 与组件校验规则

在选择、保存以及启动播放器前，均执行静态兼容性校验（不运行目标 EXE，不构成签名安全认证）：

- **共同要求**：绝对路径、文件存在且可读、符合 DOS/PE 标记、AMD64 架构、PE32+ GUI 可执行文件（拒绝 DLL、截断头、越界节表与异常入口点）。
- **PotPlayer x64**：文件名必须为 `PotPlayerMini64.exe`；若存在版本资源，`ProductName`、`FileDescription` 或 `OriginalFilename` 至少一项包含 `PotPlayer`（允许无元数据的便携版通过结构校验）。
- **VLC 3.x x64**：文件名必须为 `vlc.exe`，产品身份匹配 VLC 且主版本为 `3`；同目录下 `lua/intf/http.luac` 与 `lua/intf/modules/httprequests.luac` 必须可读（精简 Lua HTTP 的版本不可用，暂不支持 VLC 4）。

### 1.3 草稿提交与配置文件（`player-presets.json`）

路径编辑先进入草稿状态：保存后原子提交（`QSaveFile`，上限 64 KiB），取消、`Escape` 或离开页面丢弃草稿。输入回车或失焦后触发校验；粘贴路径自动清理成对双引号与首尾空白，清空路径恢复自动发现。生效路径变更会取消旧的打开事务。

```json
{
  "version": 1,
  "defaultPreset": "potplayer",
  "paths": {
    "potplayer": "",
    "vlc": ""
  }
}
```

> [!IMPORTANT]
> 应用不读取或迁移旧版 `external-players.json` 或 INI 中的 `potPlayerPath`。出现未知版本、非法类型或路径格式错误时保留原文件并拒绝启动，需修复或移走原文件后重启。

## 2. 受控实例拥有权与生命周期

所有播放器共用 `MediaPlaybackBackend` 的连接身份、媒体证据、时间轴与生命周期契约；`MediaMonitor` 按注册后端分发采样与控制，**禁止在公共任务层按播放器名称推断关闭策略**。

### 2.1 PotPlayer 受控规则

- **独立实例启动**：通过参数列表 `{视频绝对路径, "/new"}` 直接启动（不经 Shell），保留进程句柄并核实 **PID、创建时间、程序路径与所属主窗口绑定**。
- **消息通道**：同步与控制在有界工作线程通过原生窗口消息完成（状态查询上限 100 ms，定位请求上限 500 ms），请求成功后仍须等待状态或位置读回；严禁使用进程注入、内存扫描、剪贴板副作用或未验证消息编号。
- **关闭语义**：结束视频任务、明确交接至独立弹幕或退出应用时，仅请求本次拥有的 PotPlayer 正常关闭；播放器自行退出则结束对应覆盖层并保存最后有效进度。**严禁强杀、接管或关闭用户原有的其他播放器窗口**。
- **协议已知边界**：PotPlayer 原生消息当前无已验证的完整媒体路径或真实报告倍速查询接口；插值速率由有界位置历史估算，不得称为播放器报告倍速；播放器内部手动换片或自动连播下一集无法保证识别，下一集建议由 DanmaX 打开。

### 2.2 VLC 3.x 受控规则

- **受控启动与 HTTP 接口**：通过本地随机认证与固定回环监听启动独立 VLC 实例，使用官方 Lua HTTP 模块查询 `Verified` 级完整 URI 与播放列表项，不改写用户原有 VLC 配置。
- **关闭语义**：仅拥有本应用明确启动并核实 PID、创建时间与程序路径的独立实例；任务结束、取消启动、切换独立弹幕或退出应用时通过有界后台接口关闭并等待进程退出，关闭失败报告实际状态，不以隐藏覆盖层宣称播放器已退出。普通已打开的 VLC 窗口仅作为发现展示，不构成拥有权。

## 3. 媒体证据与状态契约

`MediaSample` 严格分离以下语义字段：

| 字段 | 语义边界 |
|---|---|
| `sessionToken` | 仅表示当前受控连接身份，不代表媒体内容 |
| `contentId` | 当前媒体条目标识 |
| `launchUri` / `mediaUri` | 启动目标路径与已查询当前路径分开存储，不能将启动路径伪称为查询结果 |
| 证据等级 | 分为 `Unknown`、`LaunchTarget`（PotPlayer）与 `Verified`（VLC / libVLC） |

- **换片与恢复**：窗口标题、解析结果或时长波动不能证明换片，`Unknown` 不能视为连接失效。连接暂时不可用时冻结弹幕并自动恢复；确认可靠换片仅交接内容任务、取消旧异步与旧弹窗、隔离历史并保留连接与选源；仅在明确退出或连接身份失效时才结束整个任务。
- **公共回归要求**：新增播放器后端必须通过公共契约回归，覆盖标题异常、证据缺失、采样恢复、旧请求拦截、进程退出以及关闭记录隔离（旧关闭记录禁止影响新连接）。
