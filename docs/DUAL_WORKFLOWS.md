# 弹幕与媒体库

导航保留首页、弹幕、日志、设置、关于，并增加媒体库。原播放页路由仍为 1，媒体库为 5；导航显示顺序不等于路由顺序。

## 两个工作流

| 入口 | 输入与控制 | 开始条件 |
| --- | --- | --- |
| 弹幕 | XML、首页搜索、在线与缓存来源；选择媒体会话跟随，或独立时间轴 | 点击开始，或显式开启自动匹配 |
| 媒体库 | 打开或全局拖入一个本地视频；使用默认播放器预设；为该视频选择 XML、缓存或在线来源 | 视频和播放器预检通过后开始打开事务 |

浏览页面、搜索和准备另一来源不会抢占正在播放的弹幕。明确启动另一任务时交接唯一覆盖层，清除旧活动弹幕和临时控制事务；旧来源选择可再次开始。交接不主动暂停或关闭旧视频。应用启动恢复偏好和最近列表，不自动启动视频或覆盖层。

媒体库的连接属于当前视频任务，不写入弹幕路径的 `targetSession`。视频选源弹窗只提交到该视频；首页搜索只准备弹幕路径。更换或卸载媒体任务的弹幕不取消视频连接；卸载后需显式重新匹配。播放器自行切换到未确认内容时清空旧弹幕、停止写入该视频进度，请从媒体库重新打开。

## 继续观看

最近列表提供播放／继续观看，以及有可恢复进度时的从头播放。最近条目使用当前默认播放器。记录进度满足 `5 ≤ position < duration − 10` 秒才显示继续观看。普通打开同一视频也使用有效历史进度；从头播放明确请求定位到 0。

顺序为验证文件与程序、启动或转交、确认目标媒体、恢复位置、准备弹幕。定位成功必须同时收到控制成功和 5 秒内的新位置采样；容差 1 秒并考虑播放推进。恢复失败保留原记录，提供“重试恢复”和“按当前位置继续”，确认前不覆盖原进度。播放器报告支持定位或返回请求成功，不等于已经续播成功。

PotPlayer 使用 SMTC 定位能力及请求；同名确认保护继续保留。VLC 使用受控接口，定位前再次核对连接、完整 URI 与播放列表项。真实播放器的已验证范围见 [验收记录](FRAMEWORK_STATUS.md)。

当前本机 VLC 已通过精确续播；PotPlayer 部分非零目标读回偏差超过容差，精确续播暂未验收，失败时请重试或选择按当前位置继续。

自动匹配使用所选视频文件名与已有关联；播放器原始标题用于身份核对，不伪造 SMTC 标题。手动 XML／缓存优先。曾选择的 XML 丢失时提示重新选择，不静默替换。失败或歧义会请求暂停并打开当前任务选源弹窗；仅在本次确认暂停了同一媒体后才有恢复资格，原本暂停保持暂停。

## 存储与边界

数据目录的 `recent-videos.json` 采用版本 1、原子写入、最多 100 条和 8 MiB 上限。按规范化视频路径去重，保存打开时间、位置、时长、文件大小／修改时间及来源引用，不保存 PID、端口或密码。目标确认后才新增记录；有效采样每 5 秒补写，暂停、交接、退出补写。视频大小或修改时间变化使旧进度与专属来源关联失效。

文件缺失的记录保留并显示提示，可单独移除；不删除视频或 XML。记录损坏保留原文件，当前进程仍可打开视频并维护内存列表，但不会覆盖损坏文件；保存错误显示在最近列表。

`settings.ini` 的绑定、自动匹配偏好与最近 XML 属于弹幕路径；过期 `danmax-vlc:` 绑定启动时清空。媒体匹配关联独立放在 `media/media-associations.json`，弹幕路径继续使用根目录的关联文件。播放器预设、在线服务器、主题和弹幕样式共享。

实现由 `DanmakuSession`、`MediaSession` 管理各自加载与匹配，`PlaybackCoordinator` 管理 `None / Danmaku / Media` 所有者和代次；`AppController` 保留唯一引擎、覆盖层和帧驱动。异步加载、匹配、控制和定位均验证任务身份／代次；领域核心未增加 Qt 或播放器依赖。

首轮不含目录扫描、番剧分组、海报、播放列表、下一集、通用进度拖动或直播接入。
